# Services system (July 2026)

Full reference for the hub-and-spoke services section, built on the existing `service` taxonomy. Full forge language; both page types verified at 375/768/1024/1440 in both modes.

Moved out of the main CLAUDE.md on 2026-07-03 as a long, already-shipped feature walkthrough: see CLAUDE.md's "Services system" line for the pointer back here.

## Restructure to pillars + children (July 2026)

The flat six terms became **6 parent pillars + 18 children** (two-level hierarchy), with nested URLs `/services/{pillar}/{child}/`. This supersedes several notes below (the flat list, the `order` field, the header dropdown, "no embedded form on the spokes").

- **Pillars → children** (children inherit the parent's `icon`): Web Design & Development → Web Design, Web Development, E-commerce Websites, CRO, Website Care & Support. SEO & AI Search → SEO, AI Search, Local SEO, Digital PR. Paid Media → PPC / Paid Search, Paid Social. Content Marketing → Copywriting, Video. Branding → Brand Strategy, Visual Identity. Strategy & Analytics → Marketing Strategy & Consultancy, Analytics & Reporting, Email & CRM Marketing.
- **Renamed pillars** (301s added to `vc_service_slug_redirect()`, `inc/actions.php`): `paid-socials-ppc`→`paid-media`, `content-creation`→`content-marketing`, `digital-marketing`→`strategy-analytics`. Flush rewrite rules after any slug change so nested URLs resolve.
- **`taxonomy-service.php` forks on `$term->parent`.** Pillar = hero + CTA → intro + **children grid** (`vc_service_children()` via `template-parts/service-card.php`; new `sv_children_heading_*` + `sv_children_support` fields on the `sv_` group) → process → results → aggregated work + case studies (a hierarchical `tax_query` on the parent includes children) → insights → **embedded enquiry form** → related = **sibling pillars**. Leaf = the original single-service layout (deliverables etc.) → **embedded enquiry form** → related = **sibling children**.
- **Embedded enquiry form on EVERY service page** (Gravity Form 2), pillars and children, revising the old "no embedded form on the spokes" decision. The two-column content+form band is `.service-cta`; its GF `contact-form` treatment in `service/components/_cta.scss` is now the **fourth** keep-in-sync copy (homepage contact, hub cta, contact-us main).
- **Global Service list replaces the `order` term field.** `inc/service-list-fields.php` registers a PHP ACF repeater `service_list` on the Global Settings options page: each row is a pillar (top-level-only taxonomy picker) plus `show_menu`/`show_footer`/`show_homepage`/`show_hub` toggles; row order is the pillar order. Read through **`vc_ordered_services($location)`** and **`vc_service_children($parent_id)`** in `inc/template-functions.php`. The `order` field was removed from `acf-json/services.json`. All seven consumers were repointed (homepage rail, hub grid + JSON-LD, footer, service related strip, work + case-study archive chips, mega menu); the hub/rail/footer get `parent=>0` via the helper so children never leak.
- **Dynamic mega menu.** `inc/mega-menu.php` renders "What We Do" from the taxonomy, not hand-placed child menu items: `wp_nav_menu_objects` strips the static service children (the parent keeps its `menu-item-has-children` class, set before that filter, so the caret and CSS dropdown still fire), `nav_menu_css_class` tags the item `.menu-item-mega`, and `walker_nav_menu_start_el` appends the `.sub-menu--mega` panel. SCSS `header/components/_mega.scss`: desktop is a wide bar-anchored multi-column panel (one column per pillar, top-aligned, ember-underlined heads, children stacked; the desktop nav's `ul { display:flex; align-items:center }` is overridden per column and list); mobile is a two-level accordion, with `assets/js/header/dropdown.js` extended to a shared disclosure helper for both levels. Keep any bar-state colour rule on `nav .menu > li > a` only.
- **Seeders deleted.** `inc/service-seed.php`, `inc/project-seed.php`, `inc/case-study-seed.php` and their `functions.php` requires were removed (launch scaffolding). Service/child content + Yoast title/description were written once by a throwaway `wp-load.php` migration (matched by slug; `wpseo_taxonomy_meta` + a no-op `wp_update_term` to rebuild the indexable). Copy now lives on the terms and is edited in the admin; Yoast per-term **titles** are now set (previously only the taxonomy title template). Existing `[SAMPLE]` project/case-study content is untouched.

Verified at 375/768/1024/1440 in both modes: pillar and leaf pages, the embedded form, the mega menu (desktop panel + mobile accordion), the ordering control, the redirects and the Yoast titles.

### FAQ section + card fixes (July 2026)

- **FAQ section on every service page.** New `sv_faq_heading_{start,red,end}` + `sv_faqs` repeater (`question` / `answer`) on the `sv_` group. `taxonomy-service.php` renders a `.service-faq` accordion (cloned from the free-website `.fw-faq`; identical inner classes `faq-q`/`faq-toggle`/`faq-icon`/`faq-a`) **before the CTA**, consuming a `$sv_surface()` slot. Behaviour is `assets/js/service/faq.js` (in the `service.js` bundle, server-renders open then collapses on init, reduced-motion safe); styles `service/components/_faq.scss` (no own background, surfaces paint it). It emits an aggregated **FAQPage JSON-LD** beside the Service node. Four FAQs per service are seeded (direct-answer-first, ~40-60 words, no invented figures) for AI-search citation and rich results.
- **Card descriptions.** `template-parts/service-card.php` and the homepage rail read `term_description()`, so every service term's WP **description is kept equal to its `sv_hero_subheading`** (the child terms had none, the pillars had stale copy). Setting it fixes the child cards, the pillar cards, the homepage rail and the Service JSON-LD in one place; the hero still prefers `sv_hero_subheading`. Keep the two in sync when editing.
- **Related cards** now use `variant => 'grid'` (the `.service-card--related` compact variant was removed) on both the service related strip and the case-study related row, so they match the hub/children grid cards exactly.

### Mega menu + FAQ polish (July 2026)

Follow-up fixes after the restructure review; all in `header/components/_mega.scss` + `_mobile.scss` and `taxonomy-service.php`, verified at 375/768/1024/1440 in both modes.

- **Stray red line under the bar on service pages — fixed.** The scrollspy current-page tick is `li:not(.menu-button)::after`, anchored to the LI (normally `position: relative`). `.menu-item-mega` is forced `position: static` so the panel can span the bar, which re-anchored that tick to `.main-menu` and stretched it edge-to-edge. Fix: on the mega item, disable the LI tick (`&::after { display:none }`) and redraw it on the link (`> a { position: relative }` + `> a::after`, shown on `.current-menu-item`/`.current-anchor`). Any future `position: static` nav item that is ever "current" needs the same treatment.
- **Desktop dropdown "disappears before you reach it" — fixed.** Because the panel anchors to the bar (bottom ~83px) not the link (bottom ~63px), the base `::before` hover-bridge left a dead band where the pointer lost `:hover`. The mega panel overrides the bridge to span the open gap (`top:-30px; height:30px` after the gap was tightened, see below). Verified with a real mouse parked in the former dead zone for >0.18s: panel stays open, and still closes when the pointer leaves.
- **Desktop panel proximity + width (design review, refined).** The panel floated ~26px below the bar. Fixes: `margin-top: $space-1` pulls the open panel to an ~8px gap (reads as an extension of the bar); the box is `left:0; right:0`, anchored to `.main-menu`, so it spans **the header bar itself** (24→1416 at 1440 — logo edge to theme-toggle edge), the same width as the menu (Ibrar's follow-up: the page-container width, 60→1380, read as "too short"). `padding-inline: $space-4`, `padding-block: $space-4 $space-5`. The `::before` bridge is `top:-30px; height:30px` to match the tighter gap; re-verified with a real mouse.
- **Mobile "What We Do" rebuilt as a cohesive nested menu (design review).** The old grey-Poppins-with-divider-lines list read as a settings screen grafted into the bold display menu. Now the pillars carry the menu's **Archivo display voice one step down** (`$vc-display-font`, `$vc-bold`, `font-stretch: 100%` so even "Web Design & Development" holds one line, 15px uppercase), no divider lines (rhythm from even 44px rows), the whole block indented (`padding-left: $space-3`) to show nesting, and the child services as a quieter Poppins third level indented again. **Layout gotcha:** the pillar row is a **grid** (`grid-template-columns: minmax(0,1fr) auto`) so a long name wraps inside column 1 while the chevron stays pinned to column 2 — a flex-wrap row dropped the chevron onto its own line. Focus rings are inset (`outline-offset` negative) so they never clip at the overlay's right edge. **Rotate gotcha:** the top-level rotate rule in `_mobile.scss` was a descendant selector, so opening "What We Do" rotated every nested pillar chevron up too; scoped to `> .submenu-toggle` (direct child).
- **Mobile top-level items: smaller chevron + even rows (Ibrar follow-up, supersedes the earlier "boxed chevron is approved" note).** The top-level "What We Do" disclosure was a heavy 44px bordered box; it is now a borderless 18px brand-red chevron (44px tap target kept). Every top-level item (scoped `nav ul.menu > li:not(.menu-button)`, NOT the descendant `nav ul li`, so it can't leak into the nested mega pillars/children) gets `display:flex; align-items:center; min-height:48px` for one even rhythm — the toggle row was 48px while text rows were 27px. **Root-cause gotcha for the last ~2px:** the collapsed disclosure wrapper was 4px tall, not 0, because the mega `.sub-menu--mega` inherited `padding-top:4px` from the base `.sub-menu`; that 4px offset the label's centring. Zeroing `padding-top` on the mobile `.sub-menu--mega` makes the collapsed wrapper a true 0 and the rows land at an exact 56px centre-to-centre.
- **FAQ heading.** The `sv_faq_heading` fallback is now **"Good to <span>know</span>."** (was "Common questions."): a `vc-display-2` side-column head can't fit the long word "questions" at the ≥lg widths without clipping. The head h2 also carries `overflow-wrap: break-word` as a viewport-overflow safety net for custom headings.
