# Services system (July 2026)

Full reference for the hub-and-spoke services section, built on the existing `service` taxonomy. Full forge language; both page types verified at 375/768/1024/1440 in both modes.

Moved out of the main CLAUDE.md on 2026-07-03 as a long, already-shipped feature walkthrough: see CLAUDE.md's "Services system" line for the pointer back here.

- **URLs and routing.** The taxonomy rewrite slug moved from `service` to `services`, so terms live under the hub: `/services/` (page 300, template `page-templates/page-services-hub.php`) and `/services/{slug}/` (`taxonomy-service.php`). Old `/service/*` URLs 301 via `vc_service_slug_redirect()` (`inc/actions.php`, `template_redirect` priority 0). Never create child pages under the Services page: the tax rule shadows them. `vc_service_archive_query()` (`pre_get_posts`) caps the term archives' main query to 3 posts (`no_found_rows`); it feeds the insights list. A `wpseo_breadcrumb_links` filter (`inc/filters.php`) splices the hub crumb so term pages read Home > Services. `vc_schema_type()` returns `CollectionPage` for the hub; the hub prints an `ItemList` of the six term URLs and each term page prints a `Service` node attached to the Yoast org `@id` (the About Person-nodes pattern). Yoast taxonomy title template is `%%term_title%% Services %%sep%% %%sitename%%`; per-term meta descriptions live in `wpseo_taxonomy_meta` (Yoast serves from indexables, re-save the term to rebuild).
- **Hub sections** (`sh_` fields, seeded; bundle `services-hub.js`): shared page-hero (alias `hub-hero`), `.hub-services` #FFF (split head with the shared `common/_intro-lead.scss`; six `template-parts/service-card.php` cards in `.services-grid`, taxonomy-driven, ordered by the `order` term field, staggered by `services-hub/grid.js`), `.process.hub-process` #F5F5F5 (the shared band; steps cross-read `hp_process_steps` from the front page), `.hub-proof` #FFF (shared spotlight + rating chip cross-read + `worked_with_logos` marquee), `.hub-cta` #F5F5F5 id `sh-contact` (embedded Gravity Form id 2; its GF override block in `services-hub/components/_cta.scss` is the third keep-in-sync copy). Footer CTA band hidden here and on term pages.

`no-travel` scrubs in place when the track fits) → `.results.results-anchor` (full-dark forge anchor: #121212 light, **#0D0D0D dark** so it always differs from the #121212 journey above; low-left radial glow, ember top seam, tabular red counters via shared `counter.js`, a ghost "Start a project" button under the stats; renders only when `sv_results_stats` has rows and consumes no surface slot) → `.service-work` id `work` (recent work in this service, July 2026: the shared homepage WORK WHEEL via `template-parts/work-wheel.php`, fed by up to 8 `project` posts carrying the term, newest first, imageless posts skipped, NO `.tile-service` plates (every tile is this service, so they would all repeat the page title; - **Shared pieces.** `common/_process.scss` and `common/_results.scss` were hoisted out of the `.home.page` scope (homepage visuals unchanged; page surface classes outrank their baked backgrounds). `common/_service-card.scss` (grid + related variants; watermark drifts up-left inside the clipped card on hover/focus, the allowed inner-media motion) and `common/_intro-lead.scss` are new shared partials. `services-hub/grid.js` binds `.services-grid` and ships in both new bundles. The WORK WHEEL is also shared (July 2026): markup in `template-parts/work-wheel.php` (args `projects`/`heading`/`subheading`/`stage_label`; the centre-out slotting lives in the partial), styles in `common/_work-wheel.scss` keyed off `.work-wheel` (dark overrides included; `homepage/components/_our-work.scss` keeps only the homepage section chrome), behaviour still `homepage/our-work.js` bound by the `#work-wheel` id: one wheel per page. It degrades cleanly at any card count (controls render only above 1 card; a single card sits centred).
- **Header dropdown.** "What We Do" points at `/services/` in both menus; the Main Menu carries six taxonomy child items rendered as the desktop panel and the mobile overlay accordion. The parent link carries a server-rendered chevron (`.menu-caret`, a `nav_menu_item_title` filter in `inc/filters.php`, depth-0 parent items in `main-menu` only) that rotates while the panel is open; the mobile overlay hides it because the injected disclosure button is the icon there. Desktop panel (`header/components/_desktop.scss`, simplified at Ibrar's July 2026 review: no numerals, no ticks, no row fills): solid surface in both header states, ember top seam, 300px min-width, 48px rows of plain labels whose hover/focus and current-item state simply turn `$vc-primary` (his explicit instruction; treat it like the white-on-red button as a deliberate exception, red panel labels are fine on the dark surface and accepted on light), opens on hover and `:focus-within`, Escape closes. The panel hangs 18px below the bar so it clears the Let's Talk CTA, with the invisible `::before` bridge spanning the full offset so the hover never drops crossing the gap. **The hero-active transparent header's light link colour is scoped to `nav .menu > li > a` (top level only)**: it previously leaked into the panel and washed the labels out in light mode; keep any new bar-state colour rules off `.sub-menu` descendants. Mobile accordion (`_mobile.scss` + `header/dropdown.js`, which syncs `aria-expanded`, injects the 44px disclosure chevron button, brand-red 22px chevron in both modes, `$vc-grey-400` border, and wraps the sub-list in `.submenu-wrap` for a grid-template-rows expand; no JS = the sub-list is simply visible). The mobile top-level links are sized `clamp(1.125rem, 6.2vw, 3.25rem)` with `white-space: nowrap` on the parent link so "WHAT WE DO" and its chevron ALWAYS share one line (Ibrar review; the old 8vw size pushed the chevron onto its own row at 375). The service sub-items are deliberately small and airy (Ibrar review): 15px Poppins semibold at a 56px row pitch (14px row padding + the nav ul 8px gap), 44px+ tap targets kept. The footer menu stays flat. `dropdown.js` ships in the header bundle. The homepage services rail rows link to their term pages ("Explore …"), no longer `#contact`.
- **ACF groups.** `acf-json/services-hub.json` (page-template location) and `acf-json/service-page.json` (taxonomy == service), both redesigned in place from stale April 2026 DB drafts with group keys kept. Term repeaters: `sv_deliverables` (title/description), `sv_process_steps` (empty = the sitewide homepage steps), `sv_results_stats` (`value` + `label`; real figures only, the anchor hides without rows). All six terms and page 300 are seeded; the Web Design & Development stats are `[SAMPLE]`-prefixed pending real figures.
- **Content seeder (Settings > Seed Services).** `inc/service-seed.php` fills every term's `sv_` content (intro, deliverables, process steps, Yoast description, the WebDev sample stats) in one click on any environment: the canonical launch copy lives in `vc_seed_services_content()`, terms are matched by SLUG (never ID, so staging/production term IDs don't matter), and by default only empty fields are filled (an overwrite checkbox forces a reset to the launch copy). Headings and hub copy are deliberately not seeded: they ship as ACF `default_value`s and template fallbacks. Update the seeder's copy whenever the approved launch copy changes.
